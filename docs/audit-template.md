## 审计方法论（强制标准，2026-08-24 起）

不吝时间与 token，目标是**完全解析项目、捕捉关键设计**。任何规模的项目都执行以下覆盖率门槛：

1. **核心链路 100% 亲读**：编排/主循环、Agent 定义、工具执行层、提示词**全文**（不是目录）、配置默认值、关键 schema/校验逻辑——审计者本人逐文件读，不允许只看测绘报告。子代理只可用于：文件清点、交叉验证（"论文/README 声称的机制 X 在代码哪里"）、大仓库外围层（UI/测试/生成代码）的结构登记。
2. **提示词全文精读**：提示词是这类项目的核心竞争力所在，必须逐个读完全文并在第 4.4 节给出内容级分析（纪律、防御、方法论编码），目录式罗列不合格。
3. **配置与默认值面**：所有默认值/上限/开关必须登记——默认值是设计决策的化石，常量旁的注释往往是踩坑记录。
4. **错误处理与防御性代码**：try/catch fallback、降级路径、静默吞错——行内小逻辑常常是最可移植的实战技巧，逐个记录。
5. **对照验证**：README/docs/论文声称的每个机制，找到代码落点；声称了但找不到 = 漏读或夸大，写明。
6. **反确认偏差**：项目定位的定性（如"五道闸"）必须从代码归纳，不得从 README 继承；README 说法与代码事实冲突时以代码为准并显式记录。
7. **第 8 节覆盖率如实申报**：`✅ 亲读全文` / `✅ 部分（列出未读行段）` / `⬜ 未读`；核心链路存在 ⬜ 的文档视为不合格。
